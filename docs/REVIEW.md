# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (lines 72–74) | Returns static 200 without checking MongoDB connectivity. | MongoDB is stopped or unreachable, but `/health` still returns HTTP 200. | Ping MongoDB admin database (`client.admin.command('ping')`); return HTTP 503 on failure. |
| 2 | Startup / Lifespan | No indexes are created at application startup. | Concurrency tests fail; list/analytics queries run full collection scans (`COLLSCAN`). | Implemented FastAPI `lifespan` handler creating unique and query indexes idempotently. |
| 3 | `create_employee` (lines 78–86) | Check-then-insert race condition (`find_one` followed by `insert_one`). | Concurrent POST requests with identical `emp_code` both succeed, creating duplicate records. | Enforced database unique index on `emp_code`; caught `DuplicateKeyError` and returned HTTP 409. |
| 4 | `EmployeeIn` (lines 53–61) | Missing validation for shift time inequality and employee code pattern. | Creating an employee with `shift_start == shift_end` succeeds instead of returning HTTP 422. | Added Pydantic `@model_validator` verifying `shift_start != shift_end` and regex `^EMP\d{4,6}$`. |
| 5 | `create_employee` (line 82) | `created_at` set to naive local `datetime.now()` and returned as unformatted string. | Fails schema validation requiring integer epoch milliseconds; wrong timezone stored. | Stored UTC BSON datetime in MongoDB; serialized to integer epoch milliseconds in response. |
| 6 | `list_employees` (line 93) | Off-by-one pagination bug: `skip = page * page_size`. | Requesting `page=1` skips the first 20 records; page 1 items are never returned. | Corrected offset formula to `skip = (page - 1) * page_size`. |
| 7 | `list_employees` (line 94) | `total` counts entire collection unconditionally (`count_documents({})`). | Filtering by `?department=Sales` returns total count of all employees in company. | Passed filter dictionary to count: `db.employees.count_documents(q)`. |
| 8 | `list_employees` (line 95) | Missing sort order. | Employees returned in non-deterministic order instead of sorted by `emp_code` ascending. | Added `.sort("emp_code", 1)` to MongoDB cursor. |
| 9 | `punch_in` (line 101) | Does not verify employee existence before calculating late minutes. | Non-existent `emp_code` throws unhandled 500 Internal Server Error (`KeyError: 'shift_start'`). | Added check: if `emp` is None, raise HTTP 404 (`Employee not found`). |
| 10 | `punch_in` (lines 104–105) | Check-then-insert race condition for same employee and date. | Concurrent punch-in requests for same date create duplicate records or race. | Created compound unique index on `(emp_code, date)`; caught `DuplicateKeyError` and returned HTTP 409. |
| 11 | `punch_in` (lines 102–103) | Timestamp parsed using local machine time; ignores IST and overnight shift rules. | Punch-in before `shift_end` on overnight shift is misassigned to current date instead of previous day. | Truncated ms to seconds, converted to IST, and applied overnight shift date resolution (R1). |
| 12 | `compute_late_minutes` (lines 33–38) | Truncates elapsed minutes before checking grace period: `int(secs/60) > 10`. | For shift 09:30, punch at 09:40:01 has 601s (10.016 min). `int(10.016) == 10`, fails `> 10`, returns 0 instead of 10. | Evaluated raw seconds directly: `if diff_seconds > 600: return int(math.floor(diff_seconds / 60))`. |
| 13 | `compute_late_minutes` (line 35) | `start = punch_in.replace(hour=h, minute=m)`. | On overnight shifts where punch is next morning, references current date instead of shift start date. | Constructed shift start datetime using the record's resolved attendance calendar date. |
| 14 | `compute_work_hours` (line 41) | Uses Python's built-in `round()`, implementing banker's rounding (round to even). | Halfway numbers (e.g. 8.125) round to 8.12 instead of 8.13, violating R4 half-up rule. | Implemented `Decimal` rounding with `ROUND_HALF_UP` to 2 decimal places. |
| 15 | `compute_overtime` (lines 44–48) | Missing 30-minute threshold (R3) and overnight shift end calculation. | Overtime of 15 min incorrectly counted; overnight shifts calculate negative elapsed time. | Handled next-day shift end for overnight shifts; returned 0 if elapsed minutes < 30. |
| 16 | `punch_in` & `list_attendance` | Injects synthetic `doc["id"] = str(res.inserted_id)` and returns raw BSON types. | Responses contain forbidden `id`/`_id` fields and strings instead of integer epoch milliseconds. | Stripped `_id`, excluded `id`, and formatted punch datetimes to epoch milliseconds. |
| 17 | `list_attendance` (lines 144–147) | Loads entire collection into RAM: `docs = list(db.attendance_logs.find(q))`. | At 100,000 documents, causes severe memory exhaustion, latency spikes, and timeouts. | Replaced with database-level cursor `.sort([("date", -1), ("emp_code", 1)]).skip().limit()`. |
| 18 | `list_attendance` (lines 125–132) | Missing date range validation when `date_from > date_to`. | Inverted date range returns empty list (`200 OK`) instead of required HTTP 422. | Added check: `if date_from and date_to and date_from > date_to: raise HTTPException(422)`. |

### Items Examined and Decided Were NOT Defects:
1. **`emp_code` Not Being MongoDB's `_id`:** Natural client-assigned code (`EMP0001`) is the intended business identity per contract. Internal `_id` must remain internal.
2. **Derived Fields Omitted in Client Payloads:** `work_hours`, `late_minutes`, `overtime_minutes`, and `half_day` are server-computed and read-only; ignoring them from client requests is correct.
3. **No Direct Creation Endpoint for `ABSENT` / `LEAVE`:** By design, unlogged workdays are distinct from `ABSENT` records. Absent and leave records originate strictly from seeded data or manual regularizations (`PATCH`).
